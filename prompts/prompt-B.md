# 提示词 B · 跨系统对比（两份报告都跑完后用）

````text
你有两份（或多份）Linux 实测报告文件，路径分别是：
- <报告 A 路径>
- <报告 B 路径>

请读取它们，生成一份横向对比报告，保存为：
- /home/<用户名>/bench-对比-<YYYYMMDD>.md
- 并同时复制一份到 ~/LinuxTest/reports/ 目录（便于 git 上传与跨机器比对）

要求：
0. 【运行环境一致性检查——先做这一步】
   先读两份报告的「-1. 运行环境判定」，比较运行模式与介质类型：
   - 模式相同（都是 Live，或都是已安装）→ 正常对比。
   - 模式不同（一个 Live 一个已安装）→ **禁止对性能项下结论**，
     只能对比硬件兼容性与能力探针部分，并在报告开头用醒目文字写明
     「两份数据运行环境不同，性能数值不可比」。
   - 同为 Live 但介质不同（一个 U 盘一个移动硬盘）→ 涉及磁盘 I/O 的项目一律标注不可比。
1. 逐项对照，用表格呈现。数值项给出 A、B 的具体值和相对差值（百分比）。
   凡在报告中标注了「Live 失真」或「回退方案」的数值，对比时必须保留该标注，
   且**不得**把这类数值当作决策依据，只能在表格里以灰色信息呈现。
2. 【关键】对每一项差值做显著性判断：
   - 差值 < 5%：标注「噪声范围内，不作为决策依据」
   - 差值 5–15%：标注「可感知，但需权衡代价」
   - 差值 > 15%：标注「显著差异，值得据此决策」
   不要为了让结论好看而夸大任何差异。
3. 单独列出：哪些项 A 赢、哪些项 B 赢、哪些项未测量导致无法比较。
4. 对「硬件兼容性」部分，任何一项「不通过」都要单独高亮，并说明它在现实使用中意味着什么。
5. 最后给出结论，但必须遵守：
   - 结论要区分「性能维度」和「可靠性维度」，不要用性能优势掩盖兼容性失败。
   - 如果存在未测量项影响结论，明确指出结论的不确定性，而不是假装确定。
6. 严禁编造报告里没有的数字。报告没写的就写「未测量」。
````
