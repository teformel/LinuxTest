# reports/ — 实测报告存放目录

## 命名规范

```
bench-<系统标识>-<运行模式>-<YYYYMMDD>.md
compare-<YYYYMMDD>.md
```

- 系统标识：`ubuntu2604` / `pikaos` / `cachyos`
- 运行模式：**`live`** 或 **`installed`** —— 必须区分，混在一起对比会得出错误结论
- 例：`bench-ubuntu2604-installed-20261020.md`
- 例：`compare-20261027.md`

## 可比性规则

| 情况 | 能否比性能 |
|---|---|
| `live` vs `live`（同介质） | ✅ 可比，但只代表出厂基线 |
| `installed` vs `installed` | ✅ 可比，**这才是有说服力的数据** |
| `live` vs `installed` | ❌ **禁止**，只能比硬件兼容性与能力探针 |
| 同为 `live` 但介质不同 | ❌ 磁盘 I/O 项不可比 |

**另有一条根本限制**：Live 里换不了内核、切不了 amd64v3 变体，
所以 **Live 永远测不到「优化后的系统」**。要比较调优效果，必须 `installed`。

## 人工待办清单（AI 测不了，必须自己过）

**这 6 项全部要在 `installed` 的系统上做，Live 上做的结果一律不算。**

| 项目 | 怎么测 | 通过标准 |
|---|---|---|
| **合盖睡一晚** | 睡前记下百分比，合盖，次日开机看掉了多少 | 掉电 ≤ 5% |
| **微信扫码登录** | 装官方 deb，扫码登录，语音/图片收发一次 | 能登录且消息正常 |
| **腾讯会议屏幕共享** | 实际共享一次桌面给朋友或另一台设备 | 对方能看到画面（Wayland 上最容易翻车） |
| **绝区零实际手感** | 打 30 分钟，注意着色器编译期卡顿和战斗掉帧 | 低画质 1080p 稳定 ≥30fps |
| **触控板多指手势** | 三指上滑、双指缩放、轻点 | 至少双指滚动 + 轻点可用 |
| **WiFi 稳定性** | 用一整天，注意休眠唤醒后是否断流 | 唤醒后自动重连 |

## 判读标准

### 性能维度

- 单项差 < 5% → 当作平手，**不要据此换系统**
- 真正该看的只有三项：
  1. **schbench 的 wakeup latency**（空载 vs 后台满载的**差值**）→ 决定"边编译边开 IDE 卡不卡"，i7-1260P 的 4P+8E 最对症
  2. **numpy_bench 的 GEMM / im2col 耗时** → 毕设 YOLO CPU 推理的真实代理指标
  3. **绝区零 1% low** → 平均帧率没意义，1% low 才决定打起来爽不爽

### 可靠性维度（一票否决）

- 合盖掉电 > 10% → 这台机器的 S0 待机在该系统上没配好，日常没法用
- 腾讯会议屏幕共享失败 → 秋招期间不可接受
- WiFi 休眠后不重连 → 不可接受
- 微信无法登录 → 不可接受

### 顺序不能反

**先看可靠性维度，全绿了再比性能。** 性能差 10% 换不来一次面试翻车。
